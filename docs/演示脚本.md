## 一、演示前环境准备（操作流程）

> 以下步骤在录制前完成并预演，保证演示画面连贯、无黑屏等待。

### 1. 启动后端可视化服务（三场景模型已就绪）

```cmd
cd /d "D:\Users\zzb426\Desktop\挑战杯\xiongan-traffic-control-latest"
chcp 936
python server/visualization_server.py --scenario real_peak --port 8765
```

- 启动日志应包含：`正式边缘模型已加载: edge-real-peak-onnx-v1 → model.onnx`、`WebSocket 服务器已启动 — ws://localhost:8765`
- 三场景模型映射（`server/visualization_server.py` 的 `SCENARIOS`）：
  - `real_peak` → `edge-real-peak-onnx-v1` → `models/edge/peak/model.onnx`
  - `real_offpeak` → `edge-real-offpeak-via-evening-onnx-v1` → `models/edge/evening/model.onnx`（晚高峰模型跨场景泛化）
  - `real_evening` → `edge-real-evening-onnx-v1` → `models/edge/evening/model.onnx`

### 2. 启动 Unity 前端

1. Unity Hub 打开 `frontend/CitySimulation`（Unity 2022.3.62f2c1）
2. 打开场景 `Assets/Scenes/xiong_30.unity`
3. 确认 Hierarchy 中存在 `XionganRoadBootstrap`（Map Id = `xiongan_30`）、`SimulationRuntimeDriver`、`VisualizationSystem`
4. 点击 Play，等待日志：`[SumoWS] 已连接 → ws://127.0.0.1:8765`

### 3. 固定配时对比基线（用于效果对比镜头）

```cmd
python server/visualization_server.py --scenario real_peak --port 8765 --no-model
```

- `--no-model` 时后端使用**真实定周期配时**（`data/timing_plans.json`，含保护左转相位），与 DQN 在相同路网/需求下对比。

### 4. 评估数据素材（预先导出，用于效果对比镜头）

- `docs/三场景官方对比_20260819.md` — 官方三场景对比表；录制时截取其中的 30 路口总量对比表
- `docs/轻量化验证报告_20260820.md` — 正式 FP32 ONNX 的模型体积、延迟与真实状态一致率
- 如需图表动画，使用 `scripts/generate_official_comparison.py` 基于正式评估产物预先导出；录制前先确认图表文件实际生成，避免引用不存在的 `models/dqn/*.png` 文件

## 四、注意事项与应急预案

1. **演示环境**：确保 SUMO_HOME 已设置、Python 依赖已装、端口 8765 未被占用。
2. **中文路径/编码**：cmd 中先执行 `chcp 936`；路径含中文用双引号包裹。
3. **16GB 内存约束**：录制期间**不要**同时启动训练进程，避免 SUMO 端口/内存冲突。
4. **固定配时对比**：效果对比镜头可用 `--no-model` 启动基线，或直接使用已导出的评估图表，避免现场切换耗时。
5. **应急预案**：录制一份完整备用视频；若 Unity 联调异常，演示可退回"SUMO GUI + 评估图表"路径完成全程讲解。
6. **口径一致性**：演示中所有数字与 `docs/三场景官方对比_20260819.md`、`docs/模型交付说明_20260819.md` 保持一致。
