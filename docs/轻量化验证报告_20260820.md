# 后端轻量化实施与验证报告（2026-08-20）

## 1. 结论

正式推荐部署模型为 FP32 ONNX：

| 场景 | 推荐产物 | 大小 | 真实SUMO状态动作一致率 |
|---|---|---:|---:|
| real_peak | `models/edge/peak/model.onnx` | 25.14 KB | 100% |
| real_evening | `models/edge/evening/model.onnx` | 25.14 KB | 100% |
| real_offpeak | 复用 `models/edge/evening/model.onnx` | 25.14 KB | 100% |

两份推荐模型均满足：模型大小≤1 MB、单路口推理≤100 ms、30路口批量推理≤500 ms、
动作退化≤5%。它们保持完整的 `shared-dqn-26x4-v1` 契约和绝对动作掩码语义。

## 2. 实施内容

### 2.1 26维契约修复

旧轻量化代码错误地把模型当成普通22维网络，且 teacher 指向不存在的
`dqn_pretrained.zip`。当前实现严格复现正式模型结构：

```text
26维输入 = 22维状态 + 4维动作掩码
22维状态 → 64×64 Q网络 → 4个Q值 → 绝对动作掩码 → argmax
```

导出的 TorchScript 与 ONNX 均直接接受 `(batch,26)`，不会把掩码误送入MLP，也不会
在导出后丢失无效动作约束。

### 2.2 ONNX导出

- opset：17；
- 动态batch；
- 输入：`observations`，`float32[batch,26]`；
- 输出：`q_values`，`float32[batch,4]`；
- 与正式SB3模型精确复制权重，离线和真实SUMO状态动作一致率均为100%。

### 2.3 动态量化

已生成 TorchScript INT8 和 ONNX INT8。全层INT8会显著改变窄Q值间隔下的argmax，
因此最终实现采用第一隐藏层逐通道动态INT8，后续隐藏层和4动作决策头保持FP32。

离线10,000条归一化状态上，ONNX INT8动作一致率为：

- peak：99.35%；
- evening：99.33%。

但真实SUMO轨迹上结果降为：

- peak：84.38%；
- evening：93.23%；
- offpeak（evening泛化）：92.60%。

因此INT8产物保留用于后续量化感知训练研究，但状态标记为
`experimental_failed_real_state_fidelity`，不得用于正式演示或部署。

### 2.4 结构化剪枝与蒸馏

- 隐藏层由64×64裁剪为56×56，物理删除12.5%隐藏神经元；
- 按输入/输出L1重要度选择保留通道；
- 使用20,000条契约化校准状态和正式教师Q值进行30轮蒸馏微调；
- 另用5,000条状态验证；
- 剪枝FP32离线动作一致率：peak 约96.7%，evening约97.0%；
- 剪枝INT8离线动作一致率：peak约96.6%，evening约96.9%。

剪枝模型已达到离线≤5%动作退化，但尚未通过与推荐ONNX相同规模的真实轨迹验证，
因此作为候选/消融产物保留，不替代正式推荐模型。

## 3. 性能结果

测试环境：本机CPU、ONNX Runtime CPUExecutionProvider、单线程会话、warm-up后500次。

| 模型 | 单路口 mean | 单路口 P95 | 30路口批量 mean | 30路口批量 P95 |
|---|---:|---:|---:|---:|
| peak FP32 ONNX | 0.022 ms | 0.028 ms | 0.029 ms | 0.048 ms |
| evening FP32 ONNX | 0.023 ms | 0.042 ms | 0.031 ms | 0.053 ms |

相对原正式SB3 zip（约121 KB），推荐ONNX为25,742字节，文件体积约减少79%。
由于原网络本身很小，INT8的算子和元数据开销抵消了部分权重压缩，且本机上ONNX FP32
比量化TorchScript更快；因此选择FP32 ONNX是精度、速度和体积的综合最优方案。

## 4. 真实状态验证

验证覆盖三个场景、8个代表路口（J01/J05/J10/J15/J20/J21/J25/J30），每个路口
120个连续决策状态，共2,880条真实SUMO观测。仿真由正式SB3教师动作推进，在相同
26维观测上比较候选模型动作：

| 场景 | 样本 | FP32 ONNX一致率 | 结论 |
|---|---:|---:|---|
| real_peak | 960 | 100% | PASS |
| real_offpeak | 960 | 100% | PASS |
| real_evening | 960 | 100% | PASS |

100%动作一致意味着在这些确定性轨迹上，推荐模型会执行与正式SB3模型相同的动作，
因此该验证窗口内策略reward和交通指标不会因模型格式转换而退化。

## 5. 产物清单

每个物理模型目录均包含：

| 文件 | 用途 | 当前结论 |
|---|---|---|
| `model.onnx` | FP32 ONNX | 正式推荐 |
| `model_fp32.pt` | 精确TorchScript | 通过，可作为回退 |
| `model_int8.onnx` | 动态INT8 ONNX | 真实状态精度未通过，仅实验 |
| `model_int8.pt` | 动态INT8 TorchScript | 离线通过，仅实验 |
| `model_pruned_fp32.pt` | 56×56结构化剪枝 | 离线通过，候选/消融 |
| `model_pruned_int8.pt` | 剪枝+动态INT8 | 离线通过，候选/消融 |
| `metadata.json` | 来源哈希、契约、大小和离线一致率 | 追溯信息 |

统一文件：

- `models/edge/manifest.json`：全部产物及SHA-256；
- `models/edge/validation_report.json`：离线一致率、大小和延迟；
- `models/edge/real_state_validation.json`：推荐FP32 ONNX真实状态结果；
- `models/edge/real_state_validation_int8.json`：INT8未通过的真实状态证据；
- `configs/edge_model_registry.json`：正式与实验边缘模型注册状态。
