## 1. 依赖安装问题

### 1.1 ModuleNotFoundError: No module named 'sumo_rl'

**现象**：运行训练脚本时提示找不到sumo_rl模块

**可能原因**：
1. 未正确安装sumo-rl库
2. 使用了错误的Python环境
3. 网络问题导致安装不完整

**解决方案**：

```bash
# 方法1：使用GitHub地址安装
pip install git+https://github.com/LucasAlegre/sumo-rl.git

# 方法2：手动克隆并安装
git clone https://github.com/LucasAlegre/sumo-rl.git
cd sumo-rl
pip install -e .

# 方法3：检查Python环境
which python  # Linux/Mac
where python  # Windows

# 确保使用的是正确的Python环境
conda activate xiongan_rl
pip install git+https://github.com/LucasAlegre/sumo-rl.git
```

### 1.2 ModuleNotFoundError: No module named 'traci'

**现象**：导入traci模块失败

**可能原因**：
1. 未设置SUMO_HOME环境变量
2. SUMO_HOME路径不正确

**解决方案**：

```bash
# Windows（命令行）
set SUMO_HOME=C:\Program Files (x86)\Eclipse\Sumo
set PATH=%SUMO_HOME%\bin;%PATH%

# Windows（永久设置）
# 控制面板 → 系统 → 高级系统设置 → 环境变量
# 添加系统变量：SUMO_HOME = C:\Program Files (x86)\Eclipse\Sumo
# 在PATH中添加：%SUMO_HOME%\bin

# Linux/Mac
export SUMO_HOME=/usr/share/sumo
export PATH=$SUMO_HOME/bin:$PATH

# 验证
echo %SUMO_HOME%  # Windows
echo $SUMO_HOME   # Linux/Mac
sumo --version
```

### 1.3 安装stable-baselines3失败

**现象**：安装SB3时出现错误

**可能原因**：
1. Python版本不兼容
2. 缺少编译工具

**解决方案**：

```bash
# 确保使用Python 3.8+
python --version

# 升级pip
python -m pip install --upgrade pip

# 安装stable-baselines3
pip install stable-baselines3[extra]

# 如果仍然失败，尝试降级版本
pip install stable-baselines3==2.0.0
```

## 2. SUMO环境配置问题

### 2.1 traci.start()连接失败

**现象**：运行训练脚本时，TraCI无法连接SUMO

**可能原因**：
1. SUMO配置文件路径错误
2. SUMO_HOME未正确设置
3. SUMO二进制文件未找到

**解决方案**：

```python
# 检查配置文件路径
import os
sumo_cfg_path = "sumo_files/xiongan.sumocfg"
print(f"配置文件路径: {os.path.abspath(sumo_cfg_path)}")
print(f"文件存在: {os.path.exists(sumo_cfg_path)}")

# 检查SUMO_HOME
if 'SUMO_HOME' in os.environ:
    print(f"SUMO_HOME: {os.environ['SUMO_HOME']}")
else:
    print("未设置SUMO_HOME")

# 检查SUMO二进制文件
import subprocess
try:
    result = subprocess.run(["sumo", "--version"], capture_output=True, text=True)
    print(f"SUMO版本: {result.stdout}")
except FileNotFoundError:
    print("未找到sumo命令")
```

### 2.2 信号灯ID错误

**现象**：提示找不到信号灯ID "J1"

**可能原因**：
1. 路网文件中信号灯ID不同
2. 配置错误

**解决方案**：

```python
# 在SUMO中查看信号灯ID
import traci
traci.start(["sumo", "-c", "sumo_files/xiongan.sumocfg"])
tl_ids = traci.trafficlight.getIDList()
print(f"可用信号灯ID: {tl_ids}")
traci.close()
```

### 2.3 仿真时间问题

**现象**：仿真运行时间与预期不符

**可能原因**：
1. sumocfg中设置了错误的时间范围
2. 环境中max_steps设置不当

**解决方案**：

```xml
<!-- sumocfg文件设置 -->
<time>
    <begin value="0"/>
    <end value="3600"/>  <!-- 1小时 -->
    <step-length value="1"/>
</time>
```

## 3. 训练运行问题

### 3.1 训练奖励曲线不上升

**现象**：训练过程中奖励值一直很低或波动很大

**可能原因**：
1. 状态空间设计不合理
2. 奖励函数设计不合理
3. 学习率过高或过低
4. 探索率设置不当
5. 训练步数不足

**解决方案**：

```python
# 调整DQN参数
model = DQN(
    "MlpPolicy",
    env,
    learning_rate=1e-4,        # 尝试 5e-4 或 5e-5
    gamma=0.99,                # 折扣因子
    exploration_fraction=0.2,  # 增加探索比例
    exploration_initial_eps=1.0,
    exploration_final_eps=0.01,
    buffer_size=1000000,       # 增大缓冲区
    learning_starts=5000,      # 增加预热步数
)
```

### 3.2 训练过程中报错 "Connection refused"

**现象**：TraCI连接被拒绝

**可能原因**：
1. 上一次训练未正确关闭
2. SUMO进程残留

**解决方案**：

```bash
# Windows - 结束SUMO进程
taskkill /f /im sumo.exe
taskkill /f /im sumo-gui.exe

# Linux/Mac
killall sumo
killall sumo-gui
```

### 3.3 训练过程中内存占用过高

**现象**：训练时内存占用不断增加

**可能原因**：
1. 经验回放缓冲区过大
2. 日志记录过多

**解决方案**：

```python
# 减小缓冲区大小
model = DQN(
    "MlpPolicy",
    env,
    buffer_size=50000,  # 从1000000减小到50000
)

# 或减小训练步数
total_timesteps = 50000  # 从100000减小到50000
```

## 4. TensorBoard问题

### 4.1 TensorBoard无法显示数据

**现象**：打开TensorBoard后没有数据

**可能原因**：
1. 日志目录路径错误
2. 训练尚未开始记录
3. TensorBoard版本问题

**解决方案**：

```bash
# 检查日志目录
ls logs/

# 指定正确的日志目录
tensorboard --logdir=training/logs/

# 或使用绝对路径
tensorboard --logdir=/path/to/project/logs/

# 升级TensorBoard
pip install --upgrade tensorboard
```

### 4.2 TensorBoard显示空白页面

**现象**：TensorBoard页面空白

**可能原因**：
1. 浏览器缓存问题
2. TensorBoard端口被占用

**解决方案**：

```bash
# 使用不同端口
tensorboard --logdir=logs/ --port=6007

# 清除浏览器缓存（Ctrl+Shift+Delete）
# 或使用无痕模式
```

## 5. 模型保存/加载问题

### 5.1 模型保存失败

**现象**：提示无法保存模型

**可能原因**：
1. 保存目录不存在
2. 权限不足
3. 磁盘空间不足

**解决方案**：

```python
# 确保目录存在
import os
model_dir = "./models"
os.makedirs(model_dir, exist_ok=True)

# 检查磁盘空间
import shutil
disk_usage = shutil.disk_usage("/")
print(f"可用空间: {disk_usage.free / 1024 / 1024 / 1024:.2f} GB")
```

### 5.2 模型加载失败

**现象**：提示无法加载模型

**可能原因**：
1. 模型文件路径错误
2. 模型文件损坏
3. 环境配置不匹配

**解决方案**：

```python
# 检查模型文件
model_path = "./models/dqn_traffic_final.zip"
print(f"模型文件存在: {os.path.exists(model_path)}")
print(f"文件大小: {os.path.getsize(model_path) / 1024:.2f} KB")

# 确保环境配置与训练时一致
env = TrafficSignalEnv("sumo_files/xiongan.sumocfg", use_gui=False)
model = DQN.load(model_path, env=env)
```

## 6. 性能问题

### 6.1 训练速度过慢

**现象**：训练每步耗时很长

**可能原因**：
1. 使用了GUI模式
2. SUMO配置问题
3. 硬件性能不足

**解决方案**：

```python
# 关闭GUI模式
env = TrafficSignalEnv(
    sumo_cfg_path="sumo_files/xiongan.sumocfg",
    use_gui=False,  # 训练时关闭GUI
    max_steps=3600,
    delta_time=5
)
```

```bash
# 优化SUMO配置（添加到sumocfg）
<!-- 减少输出 -->
<output>
    <tripinfo-output value=""/>
    <fcd-output value=""/>
</output>

<!-- 关闭警告 -->
<no-warnings value="true"/>
```

### 6.2 GPU未被使用

**现象**：训练时GPU占用率为0

**可能原因**：
1. 未安装CUDA
2. PyTorch未使用CUDA版本

**解决方案**：

```python
# 检查GPU是否可用
import torch
print(f"CUDA可用: {torch.cuda.is_available()}")
print(f"GPU数量: {torch.cuda.device_count()}")
print(f"当前GPU: {torch.cuda.current_device()}" if torch.cuda.is_available() else "无GPU")

# 指定使用GPU
model = DQN(
    "MlpPolicy",
    env,
    device="cuda"  # 或 "auto"
)
```
