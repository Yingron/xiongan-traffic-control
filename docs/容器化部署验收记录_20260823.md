# 容器化部署验收记录（2026-08-23）

## 1. 验收范围

本次验收使用仓库根目录的 Compose 配置构建并启动：

- `xiongan-edge`：正式 26 维 FP32 ONNX 推理服务，端口 8001；
- `xiongan-api`：FastAPI + SUMO + TraCI 服务，端口 8000。

镜像使用运行时依赖清单，不包含训练用 PyTorch/SB3/TensorBoard。镜像大小为 **413,338,108 B**（约 394 MiB）；模型和路网以只读卷挂载。

## 2. 构建与服务健康检查

执行：

```powershell
docker compose -f edge_deploy/docker/docker-compose.yml up --build -d
docker compose -f edge_deploy/docker/docker-compose.yml ps
```

结果：`xiongan-edge` 与 `xiongan-api` 均为 `healthy`。

## 3. 三个正式模型批量推理

向 `POST http://localhost:8001/predict` 发送 30 行 22 维零状态和全 1 掩码。三个正式模型都返回 `batch_size=30` 和 30 个动作。

| 模型 ID | 批量大小 | 动作数 | 本次服务端推理耗时 |
|---|---:|---:|---:|
| `edge-real-peak-onnx-v1` | 30 | 30 | 0.117141 ms |
| `edge-real-offpeak-via-evening-onnx-v1` | 30 | 30 | 0.019609 ms |
| `edge-real-evening-onnx-v1` | 30 | 30 | 0.012092 ms |

这些耗时为本次容器服务的单次模型调用，不替代 [`轻量化验证报告_20260820.md`](轻量化验证报告_20260820.md) 中 warm-up 后的统计口径。

## 4. API → ONNX Edge → SUMO 闭环冒烟验收

使用 `real_peak` 和随机种子 `20260823` 执行以下步骤：

1. `POST /api/v1/simulation/start` 创建 SUMO 会话；
2. `POST /api/v1/edge/predict` 由 API 读取当前 660 维状态、拆分为 `30×22` 并附带 `30×4` 掩码，调用边缘容器；
3. `POST /api/v1/simulation/actions` 批量写入返回的 30 个动作，推进 5 秒；
4. `GET /api/v1/simulation/state` 读取下一帧；
5. `POST /api/v1/simulation/stop` 正常释放会话。

| 项目 | 实际结果 | 结论 |
|---|---:|---|
| 初始 `transition_id` | 0 | PASS |
| 返回动作数 | 30 | PASS |
| 状态维度 | 660 | PASS |
| 执行后的 `transition_id` | 1 | PASS |
| 执行后的仿真时间 | 5.0 s | PASS |
| 会话停止 | 正常 | PASS |

结论：SUMO、TraCI、FastAPI、跨容器 ONNX 推理和 30 路口批量动作执行已在 Docker Compose 环境中完成一次实际闭环验收。

## 5. 复现与停止

复现步骤见 [`容器化部署指南_20260823.md`](容器化部署指南_20260823.md)。验收结束后可执行：

```powershell
docker compose -f edge_deploy/docker/docker-compose.yml down
```

该命令只停止本 Compose 创建的服务和网络，不会删除本地模型、路网或训练结果。
