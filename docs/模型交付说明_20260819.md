## 2. 模型参数（从 zip 元数据读取，两模型完全一致）

| 参数 | 值 |
|---|---|
| 算法 | DQN（stable-baselines3），自定义 `train()` 内 **Double-DQN** 目标 |
| 策略 | `MaskedDQNPolicy`（`training/masked_policy.py`），绝对掩码 `q = q*mask - (1-mask)*MASK_FILL`，MASK_FILL = 3.0e38 |
| 观测空间 | `Box(26,)` = 22 状态 + 4 动作掩码 |
| 动作空间 | `Discrete(4)`，4 个相位（按 `INTERSECTION_TEMPLATES` 模板，绿链长度 22 字符） |
| 网络 | MLP `[64, 64]`，**总参数 11,784** |
| 学习率 | 0.0003 |
| batch_size | 256 |
| buffer_size | 100,000 |
| train_freq / gradient_steps | 4 / 4 |
| target_update_interval | 8,000 |
| exploration | ε 1.0 → 0.1（fraction 0.5） |
| seed | 42（每个 SubprocVecEnv rank 递增） |
| 训练步数 | 1,000,000 |

## 3. 观测与动作契约

- **状态布局**：`INTERSECTION_ORDER = J01..J30`，每路口 22 维（排队长度×4 + 等待时间×4 + 占有率×4 + 溢出风险×4 + 当前相位 one-hot×4 + 时间 sin/cos×2），全路网公开状态 = **660 维**（30×22）。
- **动作**：0-3 对应模板相位（绿链字符串），同模板路口共享同一套相位；模板 A×20 / B×4 / C×3 / D×2 / E×1。
- **掩码追加协议（推理侧）**：api_server 按 `get_action_masks`（需求门控，`ACTION_MASK_QUEUE_THRESHOLD=1`）计算每路口掩码，`np.concatenate([state_660, masks_30x4], axis=1)` 拼成 26×30 后推理；掩码规则：绿链需求 < 1 → 该相位置 0，全部为空 → 回退全 1。
- **契约版本**：`shared-dqn-26x4-v1`，`state_layout_version = v1-30x22`，`normalization = none`。

## 8. 已知限制与后续（如需继续优化）

1. **offpeak 场景**：−1.6% 主要来自等待时间指标（J16 68,384s / J18 81,943s 拖尾）；根治需低流量掩码策略调整（如降低掩码阈值、右转相位动作重映射）并重训。
2. **轻流量路口切换开销**：15s MIN_GREEN 下 DQN 低流量空转；可考虑切换惩罚项或自适应最小绿灯。
3. 掩码配方为当前最佳；如需横向对比实验，建议在 8 代表路口（J01/J05/J10/J15/J20/J21/J25/J30）先扫评再上全量。
