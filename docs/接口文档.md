# 车路云协同管控平台接口规范

| 项目 | 约定 |
|---|---|
| 文档版本 | v2.0-draft |
| 维护人 | C |
| 生效范围 | 30 路口 SUMO 仿真、算法服务、Unity 可视化、边缘推理 |
| 基础地址 | `http://localhost:8000/api/v1` |
| 实时通道 | `ws://localhost:8000/api/v1/ws` |
| 编码 | UTF-8 / JSON |

> 本文是后续实现的唯一接口契约。旧版单路口 `J1`、26 维状态和单动作
> `/api/simulation/action` 仅用于原型验证，**不得**用于 30 路口集成验收。

---

## 1. 协作边界与前置条件

| 角色 | 交付/责任 | 接口依赖 |
|---|---|---|
| A（算法） | 维护共享 DQN 的22维公开状态、4维掩码、4动作、V5.1奖励语义和模型版本 | 向 C 提供模型与评估交付物 |
| B（SUMO） | 交付可加载的 30 路口 `xiongan_30.net.xml`、`xiongan_30.sumocfg`，并固定信号灯 ID、相位顺序和拓扑 | C 以其路网为 TraCI 数据源 |
| C（后端） | 实现本文 REST/WebSocket 服务、TraCI 会话和测试 | 维护协议版本与兼容性 |
| D（Unity/测试） | 按 WebSocket 推送协议展示状态，并按 REST/WS 指令控制仿真 | 不得假设旧 26 维字段 |

### 1.1 路网验收门槛

后端只有在 TraCI 查询到**恰好 30 个**可用信号灯，且可映射为 `J01` 至
`J30` 时，才允许创建可控制会话。路网不足 30 个、ID 重复、相位数不足 4
或 SUMO 无法加载时，服务返回 `503 SIMULATION_ASSET_INVALID`，不得静默用零填充。

### 1.2 路口和动作的固定约定

```text
intersection_order = [J01, J02, ..., J30]
directions         = [N, S, E, W]
```

| 动作索引 | 相位名 | 含义 |
|---:|---|---|
| 0 | `NS_Straight` | 南北直行 |
| 1 | `NS_Left` | 南北左转 |
| 2 | `EW_Straight` | 东西直行 |
| 3 | `EW_Left` | 东西左转 |

所有 30 个动作必须在同一仿真时刻批量校验、批量下发，再统一推进仿真；不允许逐路口推进导致状态时刻不一致。

## 2. 状态和奖励数据契约

### 2.1 全局状态向量

`GET /simulation/state` 必须返回 `float32` 语义的 660 个归一化数值，JSON 中以数值数组传输：

```text
state_vector.shape = [660]
state_vector[i*22 : (i+1)*22] = Ji+1 的特征
```

每个路口的 22 维切片严格遵循 [state_definition.md](state_definition.md)：

| 局部索引 | 特征 | 维度 | 范围 |
|---|---|---:|---|
| 0–3 | `queue_length`，方向 N/S/E/W | 4 | [0, 1] |
| 4–7 | `avg_wait_time`，方向 N/S/E/W | 4 | [0, 1] |
| 8–11 | `occupancy`，方向 N/S/E/W | 4 | [0, 1] |
| 12–15 | `overflow_risk`，方向 N/S/E/W | 4 | [0, 1] |
| 16–19 | `phase_onehot` | 4 | {0, 1}，恰有一个 1 |
| 20–21 | `time_feature`（sin/cos） | 2 | [-1, 1] |

除 `time_feature` 外的连续特征不得超出 [0, 1]；`state_layout_version` 固定为 `v1-30x22`。状态向量的完整索引以 `env/global_state.py` 为实现依据。

### 2.2 奖励

奖励使用当前 V5.1 吞吐驱动奖励函数，对每个路口的 22 维局部状态独立计算：

```text
reward = -(avg_queue + 0.5*max_queue + 0.3*avg_wait
           + 2.0*overflow_penalty + 0.2*switch_cost + 0.1*balance_penalty)
```

`global_reward` 是本次转换的 30 个路口奖励算术平均值，仅用于监控，不替代各路口奖励。

## 3. 通用约定

- 成功响应使用 HTTP `200`；创建仿真会话使用 `201`。
- 时间均以仿真秒 `simulation_time` 表示；`timestamp` 为 Unix 毫秒。
- `session_id` 由服务端创建，所有会改变或读取仿真状态的接口均须携带它。
- `transition_id` 从 0 单调递增。动作、奖励、状态通过该字段关联，避免 Unity/算法读取错帧。
- 后端在单个 `session_id` 内串行访问 TraCI。并发动作请求返回 `409 SESSION_BUSY`。
- 请求体 `Content-Type: application/json`；未知字段允许忽略，必填字段缺失返回 `422`。

统一错误体：

```json
{
  "error": {
    "code": "SIMULATION_ASSET_INVALID",
    "message": "SUMO network does not expose the required 30 traffic lights.",
    "details": {"expected_intersections": 30, "actual_intersections": 7}
  }
}
```

## 4. REST 接口

### 4.1 健康检查

`GET /health`

```json
{
  "status": "healthy",
  "api_version": "v1",
  "sumo_available": true,
  "active_session_id": null
}
```

### 4.2 创建仿真会话

`POST /simulation/start`

请求体（可省略，省略时使用项目默认 `xiongan_30.sumocfg`）：

```json
{
  "scenario": "real_peak",
  "use_gui": false,
  "seed": 20260726
}
```

响应：

```json
{
  "session_id": "sim_01JABC...",
  "status": "running",
  "scenario": "real_peak",
  "intersection_order": ["J01", "J02", "...", "J30"],
  "state_layout_version": "v1-30x22",
  "state_dimension": 660,
  "transition_id": 0,
  "simulation_time": 0
}
```

`use_gui=true` 仅限本地调试；后端、训练和 Unity 联调默认使用无界面 SUMO。

### 4.3 停止与重置

`POST /simulation/stop`

```json
{"session_id": "sim_01JABC..."}
```

`POST /simulation/reset`

```json
{"session_id": "sim_01JABC...", "seed": 20260726}
```

重置会清除上一回合的奖励缓存，令 `transition_id=0`，并返回新的 660 维初始状态响应。

### 4.4 查询 660 维状态

`GET /simulation/state?session_id=sim_01JABC...`

```json
{
  "session_id": "sim_01JABC...",
  "transition_id": 12,
  "timestamp": 1785052800123,
  "simulation_time": 60.0,
  "state_layout_version": "v1-30x22",
  "intersection_order": ["J01", "J02", "...", "J30"],
  "state_vector": [0.0, 0.13, 0.0, "... 共660项"],
  "intersections": [
    {
      "id": "J01",
      "state_offset": 0,
      "phase": 0,
      "phase_name": "NS_Straight",
      "queues": {"N": 0.0, "S": 0.13, "E": 0.0, "W": 0.07},
      "overflow_risk": {"N": 0.0, "S": 0.13, "E": 0.0, "W": 0.07}
    }
  ]
}
```

`intersections` 是便于 Unity 展示的状态切片，权威算法输入始终是完整的 `state_vector`。

为支持 Unity 直接连接正式 API，状态响应还携带只读 `visualization` 字段：

```json
{
  "visualization": {
    "traffic_lights": [{"id": "J01", "phase": 0, "phase_name": "NS_Straight"}],
    "vehicles": [{"id": "veh_1", "x": 200.0, "y": 800.0, "angle": 90.0, "speed": 8.4, "type": "car"}],
    "metrics": {"vehicle_count": 1, "avg_queue": 0.2, "avg_wait": 1.4, "total_arrived": 0, "total_departed": 1}
  }
}
```

这些字段与同一 TraCI 时刻的 660 维状态一起生成，仅用于渲染和 Dashboard；不能替代
`state_vector` 作为算法输入。

### 4.5 批量执行 30 路口动作

`POST /simulation/actions`

```json
{
  "session_id": "sim_01JABC...",
  "expected_transition_id": 12,
  "actions": {
    "J01": 0, "J02": 2, "J03": 0, "J04": 1, "J05": 3,
    "J06": 0, "J07": 2, "J08": 1, "J09": 0, "J10": 3,
    "J11": 0, "J12": 2, "J13": 1, "J14": 0, "J15": 3,
    "J16": 0, "J17": 2, "J18": 1, "J19": 0, "J20": 3,
    "J21": 0, "J22": 2, "J23": 1, "J24": 0, "J25": 3,
    "J26": 0, "J27": 2, "J28": 1, "J29": 0, "J30": 3
  },
  "step_seconds": 5
}
```

校验规则：

1. `actions` 必须**恰好**包含 `J01`–`J30`，不可缺失、重复或多传；
2. 每个值为整数 `0`–`3`；
3. `expected_transition_id` 必须等于当前值，否则返回 `409 STALE_TRANSITION`；
4. `step_seconds` 默认 5，范围 1–60；
5. 后端负责执行最小绿灯/黄灯安全约束。请求的动作被延迟或拒绝时，在 `applied_actions` 中返回实际相位和原因。

响应：

```json
{
  "session_id": "sim_01JABC...",
  "transition_id": 13,
  "simulation_time": 65.0,
  "requested_actions": {"J01": 0, "...": 0},
  "applied_actions": {"J01": 0, "...": 0},
  "action_result": {"J01": {"accepted": true, "reason": null}},
  "rewards_ready": true
}
```

### 4.6 查询各路口奖励

`GET /simulation/rewards?session_id=sim_01JABC...&transition_id=13`

```json
{
  "session_id": "sim_01JABC...",
  "transition_id": 13,
  "simulation_time": 65.0,
  "reward_version": "v3",
  "rewards": {
    "J01": -0.315,
    "J02": -0.482,
    "...": 0.0,
    "J30": -0.271
  },
  "global_reward": -0.338,
  "breakdown_available": false
}
```

若请求的转换尚未完成，返回 `409 REWARD_NOT_READY`。训练调试时可使用
`?include_breakdown=true` 获取 V3 的队列、等待、溢出、切换和均衡惩罚分解；生产推送默认关闭以降低负载。

### 4.7 模型推理（Stable-Baselines3 DQN）

`POST /api/v1/model/predict`

```json
{
  "session_id": "sim_01JABC...",
  "model_id": "shared-dqn-real-evening-masked-1m-v1",
  "deterministic": true
}
```

服务端从指定真实 TraCI 会话读取 660 维状态，按 `J01`–`J30` 切成
`float32[30,22]`，在同一仿真时刻计算 4 维需求门控动作掩码并拼成
`float32[30,26]`，使用同一个参数共享 SB3 DQN 批量推理并输出 30 个动作。
接口只返回预测动作，不自动执行；调用方仍需将动作提交到
`POST /api/v1/simulation/actions`，由后端执行最小绿灯约束。

正式响应：

```json
{
  "session_id": "sim_01JABC...",
  "model_id": "shared-dqn-real-evening-masked-1m-v1",
  "transition_id": 13,
  "state_layout_version": "v1-30x22",
  "deterministic": true,
  "actions": {"J01": 0, "J02": 2, "...": 0, "J30": 3},
  "inference_latency_ms": 3.2,
  "model_contract_version": "shared-dqn-26x4-v1"
}
```

为适配 Unity `JsonUtility`（不支持字典反序列化），响应同时包含下列兼容字段，原有
`actions` 字典保持不变：

- `action_masks`：30×4 二维掩码；
- `action_masks_flat`：按 J01–J30、每路口 4 项展开的 120 项掩码；
- `action_mask_shape`：固定为 `[30, 4]`；
- `actions_ordered`：按 `intersection_order` 排列的 30 项动作。

上面的 `3.2` 仅用于展示字段类型；服务会逐次返回实测推理耗时。当前注册表为
`configs/model_registry.json`，三个正式 model ID 为：

- `shared-dqn-real-peak-masked-1m-v2`：real_peak；
- `shared-dqn-real-evening-masked-1m-v1`：real_evening；
- `shared-dqn-real-offpeak-via-evening-v1`：real_offpeak，复用 evening 权重。

三者均为 `ready`、`normalization=none`，模型文件已完成 SHA-256、输入空间和动作
空间验收。历史 `shared-dqn-generalization-100k-v1` 为 `archived`，调用时返回
`503 MODEL_NOT_LOADED`。服务端不会使用随机策略、固定配时或伪造权重替代模型输出。
任何输入契约变化都必须创建新的 `model_contract_version` 和 `model_id`。

### 4.8 LLM 云脑分析（赛道 C：交通事件识别 + 管控建议）

`POST /api/v1/llm/analyze`

```json
{
  "text": "【场景】早高峰（真实需求 · 固定配时基线）\n【时间】07:05:30（仿真第 330 秒，全网车辆 468 辆）\n【路口 J25】最近 30 秒交通状态（每 5 秒采样）：\n  ...",
  "junction": "J25"
}
```

- `text`：单路口状态窗口的中文文本，由 `llm_data.text_format.format_window_text`
  渲染（场景/时钟/路口/逐采样排队、等待、占有率、均速、相位），末尾含
  【问题】指令与输出 JSON 格式约束；
- `junction`：可选，路口 ID（J01–J30），仅随响应原样返回。

服务端将文本发送给独立部署的 llama.cpp 推理服务（OpenAI 兼容
`POST <LLM_BASE_URL>/chat/completions`，默认 `http://127.0.0.1:8081/v1`），
微调模型输出经容错解析（容忍前后杂讯/单引号）并校验事件类别后返回：

```json
{
  "api_version": "v1",
  "state_layout_version": "v1-30x22",
  "junction": "J25",
  "event": "事件",
  "event_en": "incident",
  "confidence": 1.0,
  "advice": "北向检测到施工占道事件，通行速度明显下降（当前均速5km/h），建议发布绕行提示、设置限速警示，并优先放行北向疏散积压车辆。",
  "raw": "{\"event\": \"事件\", ...}",
  "latency_ms": 5565.3,
  "llm_backend": "llama.cpp",
  "llm_model": "qwen-traffic"
}
```

错误码（与既有规范一致的结构化错误）：

| code | HTTP | 触发条件 |
|------|------|---------|
| `LLM_SERVICE_UNAVAILABLE` | 503 | llama-server 未启动或不可达（检查 `LLM_BASE_URL`） |
| `LLM_SERVICE_INVALID_RESPONSE` | 503 | llama-server 返回非法 JSON |
| `LLM_BAD_RESPONSE` | 502 | 响应缺少 content 字段 |
| `LLM_PARSE_FAILED` | 502 | 模型输出无法解析为 JSON |
| `LLM_INVALID_EVENT` | 422 | 事件值不在 正常/拥堵/溢出/事件 四类 |

契约与部署说明见 [LLM部署指南_20260824.md](LLM部署指南_20260824.md)，
微调复现见 [LLM微调手把手教程_20260824.md](LLM微调手把手教程_20260824.md)。
**实现注意**：请求体不得附加 system 消息（微调数据只有 user+assistant 两段，
实测加 system 后事件召回从 100% 掉到 0%）。

## 5. WebSocket 协议（C ↔ D）

WebSocket 与 REST 由同一个 FastAPI 进程提供，共用同一个 TraCI 会话：

```text
ws://<host>:8000/api/v1/ws
```

REST会话客户端应连接本节的 `8000/api/v1/ws`，不能把 `server/visualization_server.py:8765` 的可视化快照协议当作本接口使用。8765服务当前是独立的30路口SUMO可视化通道，并不共享本API的TraCI会话语义。

连接后，客户端先发送订阅：

```json
{"type": "subscribe", "session_id": "sim_01JABC...", "channels": ["state", "reward"]}
```

服务端在会话启动、重置和每次动作转换结束后推送：

```json
{
  "type": "simulation.state",
  "session_id": "sim_01JABC...",
  "transition_id": 13,
  "simulation_time": 65.0,
  "state_layout_version": "v1-30x22",
  "state_vector": ["660项数值"],
  "intersections": ["与 REST state 接口相同的结构化切片"],
  "rewards": {"J01": -0.315, "...": -0.271},
  "global_reward": -0.338
}
```

Unity 不直接操作 TraCI；需要控制仿真时发送：

```json
{
  "type": "simulation.actions",
  "request_id": "unity-001",
  "session_id": "sim_01JABC...",
  "expected_transition_id": 13,
  "actions": {"J01": 0, "...": 3},
  "step_seconds": 5
}
```

服务端以同一个 `request_id` 返回 `simulation.action_result`；其语义与 REST
`POST /simulation/actions` 完全一致。D 应按 `transition_id` 丢弃迟到数据包。

REST 客户端执行 `POST /simulation/actions` 后，订阅了相同 `session_id` 的
WebSocket 客户端也会收到新的 `simulation.state`，因此 Unity 与训练/调试客户端
不会各自维护一套仿真状态。

连接保活支持客户端发送：

```json
{"type": "ping", "request_id": "ping-001"}
```

服务端返回 `pong`，并每 10 秒主动发送一次 `heartbeat`。协议错误使用统一格式：

```json
{
  "type": "error",
  "request_id": "unity-001",
  "error": {"code": "STALE_TRANSITION", "message": "...", "details": {}}
}
```

WebSocket 当前不接受模型预测请求，也不会生成替代动作。正式模型预测通过 REST
`/model/predict` 完成，得到的 30 个动作可通过 WebSocket 或 REST 动作端点提交。

## 6. 错误码与验收

| HTTP | code | 含义 | 调用方处理 |
|---:|---|---|---|
| 400 | `INVALID_ACTION_SET` | 30 个动作不完整或值不在 0–3 | 修正请求，不执行任何动作 |
| 404 | `SESSION_NOT_FOUND` | 会话不存在或已停止 | 重新创建会话 |
| 409 | `STALE_TRANSITION` | 使用了旧状态生成动作 | 重新读取状态再决策 |
| 409 | `SESSION_BUSY` | 同一会话有转换在执行 | 短暂退避后重试 |
| 409 | `REWARD_NOT_READY` | 奖励尚未生成 | 等待对应状态推送 |
| 422 | `REQUEST_VALIDATION_ERROR` | 请求格式不符合 JSON schema | 修正字段类型/必填项 |
| 503 | `SIMULATION_ASSET_INVALID` | 路网、信号配置或 SUMO 资源无效 | 由 B 修复资源后重试 |
| 503 | `TRACI_UNAVAILABLE` | SUMO/TraCI 会话断开 | 重置或新建会话 |
| 404 | `MODEL_NOT_FOUND` | `model_id` 未在注册表中定义 | 使用已注册的版本化模型 ID |
| 422 | `MODEL_CONTRACT_MISMATCH` | 模型输入、动作空间、归一化或校验信息不符合契约 | 由 A/C 核对模型交付元数据 |
| 503 | `MODEL_NOT_LOADED` | 模型已归档、未启用或已注册文件不存在 | 选择 `ready` 模型并检查权重路径 |
| 503 | `MODEL_LOAD_FAILED` | 权重损坏、SHA-256 不一致或 SB3 依赖不兼容 | 核对文件和运行时版本 |
| 503 | `MODEL_REGISTRY_INVALID` | 模型注册表缺失或格式错误 | 修复 `configs/model_registry.json` |
| 500 | `INFERENCE_FAILED` | SB3 在真实状态上执行预测失败 | 检查模型及输入预处理 |
| 500 | `INVALID_MODEL_OUTPUT` | 输出不是 J01–J30 的合法整数动作 | 停用该模型并重新验收 |

### 集成验收清单

- [x] B 的路网可使 `POST /simulation/start` 返回 30 个有序路口；
- [x] `GET /simulation/state` 中 `state_vector` 长度严格为 660，且每个路口切片为 22；
- [x] `POST /simulation/actions` 缺少或多出任一动作时返回 `400`，且仿真时间不变；
- [x] 合法的 30 动作请求只产生一次统一的 `transition_id` 递增；
