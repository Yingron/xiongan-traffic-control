## 1. 状态空间总览

### 1.1 维度计算

| 参数 | 值 | 说明 |
|------|------|------|
| 路口数量 | 20 | 20个信号灯控制路口 |
| 每路口特征 | 22维 | 排队长度+等待时间+占有率+溢出风险+相位+时间 |
| 总状态维度 | **440维** | 20 × 22 = 440 |
| 数据类型 | `np.float32` | 归一化后的浮点型数组 |
| 输出格式 | 一维扁平化数组 | 可直接作为DQN网络输入 |

### 1.2 特征组成结构

每个路口22维特征按以下顺序排列：

```
路口 i 的特征向量 (22维):
┌─────────────────────────────────────────────────────────────────────┐
│ 索引范围  │ 特征名称               │ 维度 │ 取值范围   │ 数据来源          │
├─────────────────────────────────────────────────────────────────────┤
│ [0:4]    │ 排队长度（归一化）     │ 4    │ [0, 1]    │ getLastStepHaltingNumber / 15  │
│ [4:8]    │ 平均等待时间（归一化） │ 4    │ [0, 1]    │ getWaitingTime平均值 / 120      │
│ [8:12]   │ 车道占有率             │ 4    │ [0, 1]    │ getLastStepOccupancy           │
│ [12:16]  │ 溢出风险               │ 4    │ [0, 1]    │ min(queue/15, 1)               │
│ [16:20]  │ 当前相位One-Hot编码    │ 4    │ {0, 1}    │ getPhase → One-Hot             │
│ [20:22]  │ 时间特征（sin/cos）     │ 2    │ [-1, 1]   │ sin(2πh/24), cos(2πh/24)      │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. 特征详细定义

### 2.1 排队长度（Queue Length）

| 项目 | 说明 |
|------|------|
| 索引范围 | `[i*22 + 0 : i*22 + 4]` |
| 方向顺序 | [北(N), 南(S), 东(E), 西(W)] |
| 原始数据 | 停车线前停止的车辆数 |
| 归一化方式 | `min(queue_length / 15, 1.0)` |
| 取值范围 | [0, 1] |
| 数据来源 | `traci.lane.getLastStepHaltingNumber(lane)` |

**物理意义**：该方向进口道排队等待的车辆数量，反映拥堵程度。最大容量15辆（假设150米车道可容纳15辆车）。

### 2.2 平均等待时间（Average Waiting Time）

| 项目 | 说明 |
|------|------|
| 索引范围 | `[i*22 + 4 : i*22 + 8]` |
| 方向顺序 | [北(N), 南(S), 东(E), 西(W)] |
| 原始数据 | 该车道所有车辆的平均等待时间（秒） |
| 归一化方式 | `min(avg_wait_time / 120, 1.0)` |
| 取值范围 | [0, 1] |
| 数据来源 | 遍历车辆ID，取 `traci.vehicle.getWaitingTime(veh_id)` 平均值 |

**物理意义**：车辆在该进口道的平均等待时长，反映延误水平。最大等待时间120秒（约2分钟）。

### 2.3 车道占有率（Lane Occupancy）

| 项目 | 说明 |
|------|------|
| 索引范围 | `[i*22 + 8 : i*22 + 12]` |
| 方向顺序 | [北(N), 南(S), 东(E), 西(W)] |
| 原始数据 | 车道占用比例 |
| 归一化方式 | 原始值（已在0~1范围） |
| 取值范围 | [0, 1] |
| 数据来源 | `traci.lane.getLastStepOccupancy(lane)` |

**物理意义**：车道空间被车辆占用的比例，反映道路利用率。

### 2.4 溢出风险（Overflow Risk）

| 项目 | 说明 |
|------|------|
| 索引范围 | `[i*22 + 12 : i*22 + 16]` |
| 方向顺序 | [北(N), 南(S), 东(E), 西(W)] |
| 原始数据 | 当前排队长度 / 最大存储容量 |
| 归一化方式 | `min(queue_length / 15, 1.0)` |
| 取值范围 | [0, 1] |
| 数据来源 | 基于排队长度计算 |

**物理意义**：排队超过车道容量的风险。值为1表示完全拥堵，存在排队溢出到上游路口的风险。

> **注意**：此特征与排队长度归一化后数值相同，但作为独立特征保留，用于强化学习模型学习不同特征组合。

### 2.5 当前相位（Current Phase）

| 项目 | 说明 |
|------|------|
| 索引范围 | `[i*22 + 16 : i*22 + 20]` |
| 编码方式 | One-Hot编码 |
| 取值范围 | {0, 1} |
| 数据来源 | `traci.trafficlight.getPhase(tl_id)` |

**相位映射表**：

| One-Hot索引 | 值为1时表示 | 相位名称 |
|-------------|-------------|----------|
| 0 | 当前执行相位0 | 南北直行（NS_Straight） |
| 1 | 当前执行相位1 | 南北左转（NS_Left） |
| 2 | 当前执行相位2 | 东西直行（EW_Straight） |
| 3 | 当前执行相位3 | 东西左转（EW_Left） |

**物理意义**：当前信号灯的相位状态，用于模型感知时序信息。

### 2.6 时间特征（Time Feature）

| 项目 | 说明 |
|------|------|
| 索引范围 | `[i*22 + 20 : i*22 + 22]` |
| 组成 | [sin(2π·hour/24), cos(2π·hour/24)] |
| 取值范围 | [-1, 1] |
| 数据来源 | 基于仿真时间计算 |

**计算公式**：
```
current_hour = sim_start_hour + (sim_time / 3600)
time_sin = sin(2π × current_hour / 24)
time_cos = cos(2π × current_hour / 24)
```

**物理意义**：周期性编码的时间特征，用于区分早晚高峰时段。sin/cos组合能表示24小时周期，且相邻时间点的值连续变化。

## 4. 车道映射规则

### 4.1 受控车道获取

```python
controlled_lanes = traci.trafficlight.getControlledLanes(tl_id)
```

获取该信号灯控制的所有进口道车道。

### 4.2 方向判断

取车道ID的第一个字符作为方向标识：

| 字符 | 方向 | 示例车道 |
|------|------|----------|
| 'N' | 北进口 | N_0, N_1, N_2 |
| 'S' | 南进口 | S_0, S_1, S_2 |
| 'E' | 东进口 | E_0, E_1, E_2 |
| 'W' | 西进口 | W_0, W_1, W_2 |

### 4.3 代表车道选择

对于每个方向，选择规则如下：

1. **优先选择直行车道**：通常以 `_0` 结尾的车道为直行车道
2. **备选方案**：若不存在直行车道，取该方向第一个车道
3. **容错处理**：若该方向没有任何受控车道，对应维度填充0

```python
def _get_representative_lane(controlled_lanes, direction):
    dir_lanes = [lane for lane in controlled_lanes if lane[0] == direction]
    if not dir_lanes:
        return None
    # 优先选择直行车道（_0结尾）
    for lane in dir_lanes:
        if lane.endswith('_0'):
            return lane
    # 返回第一个车道
    return dir_lanes[0]
```

## 5. 归一化策略

### 5.1 归一化参数

| 特征 | 原始范围 | 归一化除数 | 归一化后范围 | 截断处理 |
|------|----------|-----------|-------------|----------|
| 排队长度 | [0, 15+] | 15 | [0, 1] | 截断至1.0 |
| 平均等待时间 | [0, 120+] | 120 | [0, 1] | 截断至1.0 |
| 车道占有率 | [0, 1] | 无需 | [0, 1] | 无 |
| 溢出风险 | [0, 1] | 无需 | [0, 1] | 截断至1.0 |
| 相位One-Hot | {0, 1} | 无需 | {0, 1} | 无 |
| 时间特征 | [-1, 1] | 无需 | [-1, 1] | 无 |

### 5.2 归一化原因

1. **提高训练稳定性**：各特征量纲统一，避免梯度爆炸
2. **加速收敛**：DQN网络对输入尺度敏感
3. **特征重要性均衡**：防止某特征因数值过大主导损失函数

## 6. 关键设计说明

### 6.1 时间特征的设计考量

使用sin/cos编码而非直接使用小时数的原因：

| 方案 | 优点 | 缺点 |
|------|------|------|
| 直接使用小时数 | 直观 | 23点和0点不连续，网络难以学习周期性 |
| sin/cos编码 | 连续周期性，相邻时间点相似 | 需要两个维度 |

sin/cos组合形成单位圆上的点，24小时完成一个周期，相邻时间点的特征值连续变化。

### 6.2 溢出风险的设计考量

在"窄路密网"场景下（路口间距<200m），排队溢出是关键问题：

- 当排队超过车道容量时，车辆会阻塞上游路口
- 溢出风险特征提醒模型优先处理高风险方向
- 与排队长度的区别：溢出风险强调"超容"状态

### 6.3 容错机制

- **方向缺失处理**：若某方向无受控车道，对应维度填充0
- **相位越界处理**：若相位索引超出0~3范围，默认设为相位0
- **路口数量容错**：若实际信号灯数量少于20个，剩余位置填充0

## 9. 附录

### 9.1 440维完整索引速查表

**路口J01（0-21），J02（22-43），...，J20（396-415）**

每个路口内部结构相同：
- [0:4] 排队长度（N,S,E,W）
- [4:8] 平均等待时间（N,S,E,W）
- [8:12] 车道占有率（N,S,E,W）
- [12:16] 溢出风险（N,S,E,W）
- [16:20] 相位One-Hot（0,1,2,3）
- [20:22] 时间特征（sin, cos）

### 9.2 设计原则

1. **固定顺序**：特征顺序严格固定，确保训练和推理一致
2. **归一化**：所有数值特征归一化到[0,1]范围（时间特征除外）
3. **容错性**：处理缺失数据和异常值
4. **可扩展性**：支持任意数量路口（默认20个）
5. **可调试性**：提供详细的调试日志和辅助解析函数
