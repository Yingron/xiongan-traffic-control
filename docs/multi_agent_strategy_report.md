## 1. 策略对比分析

### 1.1 三种策略概述

| 策略 | 核心思想 | 状态空间 | 动作空间 |
|------|---------|---------|---------|
| **全局单智能体** | 一个DQN控制所有20个路口 | 440维（全局） | 80维或20个独立动作 |
| **独立DQN（IQL）** | 每个路口一个独立DQN | 22维/路口 | 4维/路口 |
| **集中训练-分散执行（CTDE）** | 训练时用全局信息，执行时用局部 | 训练时440维，执行时22维 | 4维/路口 |

### 1.2 四维对比分析

#### 维度一：训练效率

| 策略 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| **全局单智能体** | 无需协调，端到端学习 | 状态空间大（440维），动作空间组合爆炸，训练慢 | ⭐⭐ |
| **独立DQN** | 状态空间小（22维），训练快，可并行 | 无法感知相邻路口状态，溢出协同能力弱 | ⭐⭐⭐⭐ |
| **CTDE（QMIX/VDN）** | 兼顾全局信息和分散执行 | 网络结构复杂，训练开销大，超参数敏感 | ⭐⭐⭐ |

#### 维度二：可扩展性

| 策略 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| **全局单智能体** | 理论上支持任意数量路口 | 状态/动作空间随路口数线性增长，扩展性差 | ⭐⭐ |
| **独立DQN** | 网络结构固定，天然支持任意数量路口 | 无 | ⭐⭐⭐⭐⭐ |
| **CTDE** | 执行时可扩展 | 训练时网络结构需随路口数调整 | ⭐⭐⭐⭐ |

#### 维度三：通信开销

| 策略 | 训练时通信 | 执行时通信 | 评分 |
|------|-----------|-----------|------|
| **全局单智能体** | 需全局状态（高） | 需全局状态（高） | ⭐⭐ |
| **独立DQN** | 仅需单路口状态（低） | 仅需单路口状态（低） | ⭐⭐⭐⭐⭐ |
| **CTDE** | 需全局状态（高） | 仅需局部状态（低） | ⭐⭐⭐⭐ |

#### 维度四：溢出协同能力

| 策略 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| **全局单智能体** | 全局视野，可优化整体溢出风险 | 训练困难，难以学到有效策略 | ⭐⭐⭐ |
| **独立DQN** | 无直接协同，依赖奖励函数中的溢出惩罚间接协调 | 协同能力有限 | ⭐⭐⭐ |
| **CTDE** | 训练时感知全局，执行时独立决策 | 协同能力强，但实现复杂 | ⭐⭐⭐⭐⭐ |

### 1.3 综合对比表

| 策略 | 训练效率 | 可扩展性 | 通信开销 | 溢出协同 | 推理延迟 | 综合评分 |
|------|---------|---------|---------|---------|---------|---------|
| **全局单智能体** | ⭐⭐ | ⭐⭐ | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| **独立DQN** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| **CTDE** | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |

## 2. 预选方案

### 2.1 预选策略：独立DQN + 参数共享 + 共享经验回放

**核心思想**：所有20个路口使用**同一个DQN网络**（参数共享），每个路口独立决策（22维输入，4维输出），经验存储在共享的回放缓冲区中。

### 2.2 预选理由

| 理由 | 说明 |
|------|------|
| **训练效率高** | 状态空间仅22维，DQN训练快速收敛 |
| **可扩展性强** | 网络结构固定，新增路口无需修改网络 |
| **通信开销低** | 训练和执行均仅需单路口状态 |
| **推理延迟低** | 单路口推理时间<1ms，20路口并行<5ms |
| **实现简单** | 无需复杂的多智能体算法框架 |
| **资源友好** | 单机CPU/GPU即可训练 |

### 2.3 溢出协同机制

虽然独立DQN没有显式的全局视野，但通过以下机制实现间接协同：

1. **奖励函数中的溢出惩罚**：每个路口的奖励函数包含溢出惩罚项，当排队接近阈值时给予强惩罚
2. **共享经验回放**：不同路口的经验混合训练，网络学习到通用的信号控制策略
3. **邻居状态增强（可选）**：在22维基础状态上增加相邻路口的排队信息

### 2.4 与CTDE的权衡

| 维度 | 独立DQN（推荐） | CTDE（QMIX/VDN） |
|------|---------------|-----------------|
| 实现复杂度 | 低 | 高 |
| 训练速度 | 快 | 慢 |
| 超参数敏感性 | 低 | 高 |
| 协同能力 | 中等（间接） | 强（直接） |
| 硬件需求 | 低（单机） | 高（多GPU） |

**结论**：对于20路口规模和2周训练时间，独立DQN是更务实的选择。

## 3. 实现框架设计

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    SUMO仿真环境                              │
│  ┌──────┐ ┌──────┐ ┌──────┐ ... ┌──────┐                    │
│  │ J01  │ │ J02  │ │ J03  │ ... │ J20  │                    │
│  └──┬───┘ └──┬───┘ └──┬───┘ ... └──┬───┘                    │
└─────┼────────┼────────┼────────────┼───────────────────────┘
      │        │        │            │
      ▼        ▼        ▼            ▼
┌─────────────────────────────────────────────────────────────┐
│                    共享DQN网络                               │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 输入: 22维状态 → 隐藏层 → 输出: 4维Q值                  │    │
│  │ 所有路口共享同一网络参数                                │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
      │        │        │            │
      ▼        ▼        ▼            ▼
┌─────────────────────────────────────────────────────────────┐
│                   共享经验回放缓冲区                           │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 存储: (state, action, reward, next_state, done,      │    │
│  │        agent_id)                                    │    │
│  │ 采样: 随机混合不同agent的经验                           │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 关键设计

#### 3.2.1 环境包装层

- 使用 `get_global_state()` 获取440维全局状态
- 按路口切片：`state[i*22:(i+1)*22]` 获取第i个路口的22维状态
- 每个路口独立计算奖励（使用V3奖励函数）
- 动作执行：批量设置所有路口相位后再推进仿真

#### 3.2.2 共享DQN网络

- 输入：22维（单路口状态）
- 输出：4维Q值（4个相位）
- 结构：MLP（256→128→4）
- 优化器：Adam，学习率1e-4
- 目标网络更新间隔：2000步

#### 3.2.3 经验回放缓冲区

- 容量：500,000条
- 每条记录：`(state, action, reward, next_state, done, agent_id)`
- 采样策略：均匀采样，混合不同agent的经验
- 批大小：64

#### 3.2.4 训练流程

1. **初始化**：启动SUMO，获取所有信号灯ID
2. **重置**：获取全局状态，按路口切片
3. **动作选择**：每个路口独立ε-贪婪选择动作
4. **执行动作**：批量设置所有路口相位，推进仿真
5. **收集经验**：获取新状态，计算每个路口奖励，存入buffer
6. **网络更新**：每隔一定步数，从buffer采样批量更新网络
7. **探索率衰减**：从1.0线性衰减至0.01（前30%步数）

### 3.3 邻居状态增强（可选增强）

**动机**：窄路密网下（路口间距<200m），相邻路口的排队状态对当前路口决策有重要影响。

**实现方案**：

```python
# 在22维基础状态上增加邻居信息
# 假设每个路口最多有4个邻居（上、下、左、右）
# 增加4×2=8维：邻居排队长度 + 邻居溢出风险

def get_enhanced_state(base_state, neighbor_states):
    """
    获取增强状态（基础状态 + 邻居信息）
    
    Args:
        base_state: 22维基础状态
        neighbor_states: 邻居路口的状态列表
    
    Returns:
        np.ndarray: 增强后的状态（30维）
    """
    enhanced = base_state.copy()
    
    # 为每个邻居添加排队长度和溢出风险
    for ns in neighbor_states[:4]:  # 最多4个邻居
        enhanced = np.concatenate([enhanced, ns[0:4], ns[12:16]])
    
    # 如果邻居不足4个，填充0
    while len(enhanced) < 30:
        enhanced = np.append(enhanced, 0)
    
    return enhanced
```

**增强后状态空间**：30维（22维基础 + 8维邻居）

## 5. 风险评估与应对

### 5.1 风险清单

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| 训练不收敛 | 中 | 高 | 调整学习率、探索率、奖励函数 |
| 溢出协同不足 | 高 | 中 | 添加邻居状态增强、调整溢出惩罚权重 |
| 推理延迟超标 | 低 | 高 | 优化网络结构、使用量化推理 |
| 仿真环境不稳定 | 中 | 中 | 添加异常处理、定期重启仿真 |

### 5.2 监控指标

| 指标 | 监控方式 | 目标值 |
|------|---------|-------|
| 平均排队长度 | 训练日志 | <0.3（归一化） |
| 平均奖励 | 训练日志 | >-0.5 |
| 溢出事件次数 | 评估脚本 | <10次/小时 |
| 推理延迟 | 性能测试 | <5ms |

## 6. 结论

### 6.1 预选策略

**独立DQN + 参数共享 + 共享经验回放**是20路口窄路密网场景的最优选择：

- ✅ 训练效率高：22维状态，训练快速收敛
- ✅ 可扩展性强：天然支持任意数量路口
- ✅ 通信开销低：无需全局通信
- ✅ 推理延迟低：<5ms满足边缘端要求
- ✅ 实现简单：单机即可训练
