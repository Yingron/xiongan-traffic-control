# 系统完整启动手册（2026-08-25 实测版）

> 适用范围：30 路口正式系统（Unity + WebSocket + SUMO + DQN 边缘模型 + LLM 云脑）。
> 本文所有启动命令均已在本机（RTX 4070 / Win11 / Python 3.14）实测验证。

---

## 1. 系统组成与端口总览

| 服务 | 端口 | 进程/入口 | 作用 |
|------|------|----------|------|
| `xiongan-api` | **8000** | `python server/api_server.py` | REST 网关（会话/状态/动作/模型预测/**LLM analyze**）+ WebSocket `ws://host:8000/api/v1/ws` |
| `visualization_server` | **8765** | `python server/visualization_server.py` | Unity 主链路：SUMO 仿真 + 正式 ONNX 边缘模型推理 + WebSocket 快照广播 |
| `llama-server` | **8081** | `tools/llama.cpp/llama-server.exe` | LLM 云脑（微调 Qwen2.5-0.5B f32 GGUF，OpenAI 兼容接口），被 8000 的 `/llm/analyze` 调用 |
| Unity 前端 | — | Unity 2022.3.62f2 打开 `frontend/CitySimulation` | 30 路口三维可视化（场景 `Assets/Scenes/xiong_30.unity`） |
| SUMO | 8814（自动） | 由 visualization_server 拉起 | 交通流仿真引擎（`SUMO_HOME` 已系统配置） |

**主链路**：`Unity → WebSocket 8765 → visualization_server → (SUMO 状态 → ONNX DQN 推理 → 动作写回) → 快照广播 → Unity 刷新`
**REST 能力**：`客户端 → 8000 → (660 维状态 / 模型预测 / LLM 云脑分析)`
**LLM 云脑**：`8000 的 /api/v1/llm/analyze → llama-server 8081 → 微调模型`

## 2. 前置条件

| 项目 | 要求 | 本机状态 |
|------|------|---------|
| SUMO | ≥ 1.18（`SUMO_HOME` 环境变量指向 bin 目录） | ✅ `C:\Program Files (x86)\Eclipse\Sumo\` |
| Python | 3.10+（含 fastapi/uvicorn/websockets/numpy/torch/transformers） | ✅ 3.14 |
| 正式模型 | `models/edge/*/model.onnx`（DQN 边缘）、`models/llm/gguf/qwen-traffic-f32.gguf`（LLM） | ✅ 已交付 |
| 端口可用 | 8000 / 8765 / 8081 未被占用 | 启动前用下方命令检查 |

```bash
# 检查端口占用（有输出 = 被占用，先关闭对应进程）
netstat -ano | grep -E ":8000|:8765|:8081" | grep LISTENING
```

## 3. 启动顺序（共 4 步）

### 第 1 步：LLM 云脑服务（可选，仅演示 LLM 告警时需要）

```bash
cd "C:\Users\荣光\Desktop\挑战杯\xiongan-traffic-control\tools\llama.cpp"
./llama-server.exe -m ../../models/llm/gguf/qwen-traffic-f32.gguf \
    --host 127.0.0.1 --port 8081 --n-gpu-layers 99 -c 4096 \
    --alias qwen-traffic --repeat-penalty 1.0
```

验证：
```bash
curl http://127.0.0.1:8081/v1/models   # 返回 {"models":[{"name":"qwen-traffic",...}]}
```

> ⚠️ 此进程依附于所在终端窗口，关闭窗口即停服；演示期间请保持窗口打开。
> 必须使用 f32 模型 + GPU 层（INT4/INT6 量化会破坏事件判别，见 `docs/LLM部署指南_20260824.md`）。

### 第 2 步：可视化服务（Unity 主链路）

```bash
cd "C:\Users\荣光\Desktop\挑战杯\xiongan-traffic-control"
python server/visualization_server.py --scenario real_peak
```

参数说明：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--scenario` | real_peak | 启动场景：`real_peak`/`real_offpeak`/`real_evening`（Unity 内可再切换） |
| `--port` | 8765 | WebSocket 端口 |
| `--no-model` | 关 | 不加载 DQN 模型（固定配时基线对比演示用） |
| `--no-llm` | 关 | 不启动 LLM 云脑自动诊断（第 1 步 llama-server 未启动时可加） |
| `--llm-interval` | 60 | LLM 云脑自动诊断间隔（秒；诊断 1 次约 5~9 秒，慢周期决策） |
| `--gui` | 关 | 以 SUMO GUI 窗口运行（调试用） |

### 第 3 步：REST API 网关（能力演示 + LLM 分析入口）

```bash
cd "C:\Users\荣光\Desktop\挑战杯\xiongan-traffic-control"

```

验证：
```bash

# 预期: {"status":"healthy","api_version":"v1","sumo_available":true,...}
```

常用接口速查（完整契约见 `docs/接口文档.md`）：

```bash
# 创建仿真会话（任意场景）
curl -X POST http://127.0.0.1:8000/api/v1/simulation/start \
  -H "Content-Type: application/json" -d '{"scenario": "real_peak", "seed": 42}'
# 查询 660 维状态
curl "http://127.0.0.1:8000/api/v1/simulation/state?session_id=<上一步返回的 session_id>"
# DQN 模型预测
curl -X POST http://127.0.0.1:8000/api/v1/model/predict \
  -H "Content-Type: application/json" \
  -d '{"session_id": "<session_id>", "model_id": "shared-dqn-real-peak-masked-1m-v2", "deterministic": true}'
# LLM 云脑分析（需第 1 步 llama-server 在运行；text 由 llm_data.text_format 渲染）
curl -X POST http://127.0.0.1:8000/api/v1/llm/analyze \
  -H "Content-Type: application/json" \
  -d '{"text": "【场景】早高峰…【路口 J25】最近 30 秒交通状态…", "junction": "J25"}'
# 停止会话
curl -X POST http://127.0.0.1:8000/api/v1/simulation/stop \
  -H "Content-Type: application/json" -d '{"session_id": "<session_id>"}'
```

### 第 4 步：Unity 前端

1. 用 **Unity Hub** 打开 `frontend/CitySimulation`（Unity 2022.3.62f2c1）；
2. 打开场景 `Assets/Scenes/xiong_30.unity`；
3. 点击 **Play**；
4. 右上角可切换 `real_peak / real_offpeak / real_evening` 三场景（后端自动重启 SUMO、切换模型、清空指标）。

验收：30 盏信号灯随相位变化、车辆流动、指标面板实时刷新；切换场景后 5 秒内恢复快照。

**AI 云脑诊断面板**（屏幕右侧中部，VisualizationBootstrap 自动挂载）：
- 连接后约 2 秒自动发起首次诊断，此后后端每 60 秒诊断一次全网最异常路口并推送；
- 面板显示 路口/事件类别（正常绿·拥堵黄·溢出橙·事件红）/置信度/仿真时刻/中文管控建议；
- 「立即诊断」随时刷新；「诊断 J25（施工点）」演示指定路口（构造扰动高发路口）；
- 第 1 步 llama-server 未启动时面板显示"云脑离线：LLM_SERVICE_UNAVAILABLE..."。

## 5. Docker 替代方案（可选，替代第 2/3 步）

```bash
cd edge_deploy/docker
docker compose up --build -d          # xiongan-edge:8001 + xiongan-api:8000
docker compose ps                      # 预期两个 healthy
Invoke-RestMethod http://localhost:8001/health
Invoke-RestMethod http://localhost:8000/api/v1/health
docker compose down                    # 停止（保留镜像）
```

> 容器版 api_server 默认 `LLM_BASE_URL=http://127.0.0.1:8081/v1`（Windows 本地 llama-server）；
> 若要容器内联 LLM，追加 `xiongan-llm` 服务并设置 `LLM_BASE_URL=http://xiongan-llm:8081/v1`
> （配置见 `docs/容器化部署指南_20260823.md` 第 8 节）。

## 6. 停止方法

| 服务 | 停止方式 |
|------|---------|
| llama-server | 关闭其终端窗口，或 `taskkill //PID <进程号> //F`（`netstat -ano | grep 8081` 查 PID） |
| visualization_server | `Ctrl+C` 关闭终端，或 `taskkill //PID <进程号> //F` |
| api_server | 同上（端口 8000） |
| Docker | `docker compose down` |

## 7. 常见问题排查

| 现象 | 原因 | 处理 |
|------|------|------|
| `Address already in use` / 端口占用 | 旧服务进程残留 | `netstat -ano | grep <端口>` → `taskkill //PID <PID> //F` |
| Unity 无车辆/无快照 | 8765 可视化服务未启动 | 启动第 2 步服务后，Unity 会自动重连（已实现自动重连） |
| `/llm/analyze` 返回 `LLM_SERVICE_UNAVAILABLE` | llama-server 未运行 | 启动第 1 步；`curl http://127.0.0.1:8081/v1/models` 确认 |
| Unity 面板显示"云脑离线：..." | llama-server 未启动或未加 `--alias qwen-traffic` | 启动第 1 步后点面板「立即诊断」重试 |
| 面板提示未知路口 | 手动指定了非 J01-J30 路口 | 用 J01~J30 内的路口 ID 或直接点「立即诊断」 |
| `MODEL_NOT_LOADED` | 误用 archived 模型 ID | 用 `configs/model_registry.json` 中 `ready` 的三个正式 ID |
| SUMO 启动失败 | `SUMO_HOME` 未配置 | `set SUMO_HOME=C:\Program Files (x86)\Eclipse\Sumo` 后重开终端 |
| 场景切换后车辆卡住 | 偶发 TraCI 时序 | 等待 5 秒自动恢复；或重启可视化服务 |
| GPU 显存不足（LLM） | 其他 GPU 任务占用 | 关闭占用程序；llama-server 可改 `--n-gpu-layers 0`（CPU，慢约 3 倍） |
