## 3. 仿真环境构建方法

### 3.1 路网设计与构建

#### 3.1.1 路网拓扑
- **规模**：30路口网格布局（6×5）
- **节点类型**：边界节点（priority）+ 内部路口（traffic_light）
- **道路参数**：双向3车道，限速50km/h（13.89m/s）
- **路口间距**：约500m（符合窄路密网特征）
- **图表建议**：30路口网格拓扑示意图（标注J01–J30、边界节点N/S/E/W）

#### 3.1.2 路网生成与验证流程
- **生成工具**：SUMO netconvert
- **验证内容**：J01–J30全部为traffic_light类型，每路口4个有效动作，N/S/E/W映射完整

#### 3.1.3 信号灯规范化
- **问题**：原始路网相位1和相位3为黄灯，不能作为有效RL动作
- **解决方案**：规范为每路口4个可控相位

#### 3.1.4 安全优化
- **措施**：将右转和掉头连接改为让行绿灯`g`，消除SUMO的`Unsafe green`冲突
- **复验结果**：1,527辆到达，平均等待0.94秒，平均行程58.60秒，0碰撞，0传送

### 3.2 交通流配置

#### 3.2.1 多时段交通流
| 时段 | 流量特征 | 目标车辆数 |
|------|---------|-----------|
| 早高峰(7-9点) | 南北向为主，流量最大 | ~19,104 |
| 平峰(11-14点) | 流量均衡 | ~2,773 |
| 晚高峰(17-19点) | 南向流出为主 | ~19,104 |

- **图表建议**：三时段交通流时空分布对比图

#### 3.2.2 检测器配置
- **环形检测器（e1Detector）**：采集排队长度、占有率
- **进出检测器（entryExitDetector）**：统计通过车辆数、行程时间

### 3.3 静态配时优化
- **目标函数**：`平均等待时间 + 0.1 × 平均行程时间`（碰撞和传送重罚）
- **对比结果**：

| 配时方案 | 相位时长(秒) | 到达车辆 | 平均等待(s) | 平均行程(s) | 得分 |
|---------|------------|---------|-----------|-----------|------|
| balanced | 30/12/30/12 | 1,527 | 0.93 | 58.46 | **6.776** |
| throughput_favored | 36/8/36/8 | 1,549 | 0.93 | 59.31 | 6.861 |
| turn_protection | 30/16/30/16 | 1,512 | 0.93 | 62.66 | 7.196 |

- **结论**：balanced方案最优，已应用到路网配置

### 3.4 仿真环境验证
- **历史20路口集成测试（非当前30路口验收）**：600秒仿真，1,540辆到达，0碰撞，0传送，平均等待12.83秒，平均行程50.83秒
- **J01随机动作测试**：100步，平均奖励-0.5600，平均排队4.38辆，相位切换/最小绿灯/黄灯过渡均正常

## 4. 协同管控算法核心原理

### 4.1 算法选型分析

#### 4.1.1 三种多智能体策略对比

| 策略 | 核心思想 | 状态空间 | 动作空间 |
|------|---------|---------|---------|
| 全局单智能体 | 一个DQN控制所有30路口 | 660维（全局） | 120维或30个独立动作 |
| 独立DQN（IQL） | 每路口一个独立DQN | 22维/路口 | 4维/路口 |
| CTDE（QMIX/VDN） | 训练时用全局信息，执行时用局部 | 训练660维/执行22维 | 4维/路口 |

#### 4.1.2 四维评估

| 维度 | 全局单智能体 | 独立DQN | CTDE |
|------|------------|---------|------|
| 训练效率 | ⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| 可扩展性 | ⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 通信开销 | ⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 溢出协同 | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| 推理延迟 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

#### 4.1.3 选型结论
- **选定方案**：**独立DQN + 参数共享 + 共享经验回放**
- **核心理由**：训练效率高、可扩展性强、通信开销低、推理延迟低（<5ms）、实现简单

### 4.2 DQN算法原理

#### 4.2.1 Q学习基础
- **填充内容**：Bellman方程、Q值更新规则、γ折扣因子意义
- **公式建议**：Q(s,a) ← Q(s,a) + α[r + γ·max Q(s',a') - Q(s,a)]

#### 4.2.2 深度Q网络（DQN）
- **核心创新**：用神经网络近似Q函数，解决传统Q学习的维度灾难
- **关键技术**：
  - 经验回放（Experience Replay）：打破样本相关性
  - 目标网络（Target Network）：稳定训练目标
  - ε-贪婪探索：平衡探索与利用
- **图表建议**：DQN算法结构示意图

#### 4.2.3 参数共享机制
- **核心思想**：所有20个路口使用**同一个DQN网络**，每个路口独立决策
- **输入**：22维（单路口状态）
- **输出**：4维Q值（4个相位）
- **优势**：网络结构固定，新增路口无需修改网络；不同路口经验混合训练，学习通用策略

### 4.3 状态空间定义

#### 4.3.1 全局状态向量（660维）
- **维度计算**：30路口 × 22维/路口 = 660维
- **数据类型**：np.float32，归一化后的一维扁平化数组

#### 4.3.2 单路口22维特征结构

| 索引范围 | 特征名称 | 维度 | 取值范围 | 归一化方式 |
|---------|---------|------|---------|-----------|
| [0:4] | 排队长度（N/S/E/W） | 4 | [0, 1] | min(queue/15, 1.0) |
| [4:8] | 平均等待时间（N/S/E/W） | 4 | [0, 1] | min(wait/120, 1.0) |
| [8:12] | 车道占有率（N/S/E/W） | 4 | [0, 1] | 原始值 |
| [12:16] | 溢出风险（N/S/E/W） | 4 | [0, 1] | min(queue/15, 1.0) |
| [16:20] | 当前相位One-Hot | 4 | {0, 1} | getPhase→One-Hot |
| [20:22] | 时间特征（sin/cos） | 2 | [-1, 1] | sin(2πh/24), cos(2πh/24) |

- **图表建议**：22维特征结构可视化图

#### 4.3.3 关键特征设计考量
- **时间特征sin/cos编码**：解决23点与0点不连续问题，保证周期性连续
- **溢出风险特征**：针对窄路密网场景，强调"超容"状态，提醒模型优先处理高风险方向
- **相位One-Hot编码**：让模型感知当前时序状态

### 4.4 动作空间定义

| 动作索引 | 相位名 | 含义 |
|---------|--------|------|
| 0 | NS_Straight | 南北直行 |
| 1 | NS_Left | 南北左转 |
| 2 | EW_Straight | 东西直行 |
| 3 | EW_Left | 东西左转 |

- **安全约束**：最小绿灯15秒，黄灯过渡3秒

### 4.5 奖励函数设计（V3）

#### 4.5.1 奖励公式
```
reward = -(avg_queue + 0.5*max_queue + 0.3*avg_wait
          + 2.0*overflow_penalty + 0.2*switch_cost + 0.1*balance_penalty)
```

#### 4.5.2 各分量详解
| 分量 | 权重 | 物理意义 | 计算方式 |
|------|------|---------|---------|
| avg_queue | 1.0 | 平均排队长度 | mean(queue_lengths[0:4]) |
| max_queue | 0.5 | 最大排队长度（公平性） | max(queue_lengths[0:4]) |
| avg_wait | 0.3 | 平均等待时间 | mean(wait_times[4:8]) |
| overflow_penalty | 2.0 | 溢出惩罚（安全性） | max(overflow_risks[12:16]) |
| switch_cost | 0.2 | 切换成本（稳定性） | 1.0 if action≠prev_action else 0.0 |
| balance_penalty | 0.1 | 均衡惩罚（fairness） | std(queue_lengths) |

- **图表建议**：奖励函数各分量权重饼图

#### 4.5.3 设计理念
- **多目标均衡**：兼顾效率（排队/等待）、公平（max_queue/balance）、安全（overflow）、稳定（switch）
- **溢出惩罚高权重（2.0）**：针对窄路密网排队溢出风险
- **全局奖励**：30路口奖励算术平均值，仅用于监控

## 5. 算法设计思路

### 5.1 总体设计理念
- **参数共享**：30路口共用一个网络，降低参数量，提升泛化能力
- **分布式决策**：每个路口独立观测、独立决策，通信开销低
- **间接协同**：通过共享经验和溢出惩罚实现路口间间接协调

### 5.2 整体架构
- **图表建议**：绘制SUMO环境↔共享DQN↔经验回放缓冲区的交互架构图

### 5.3 溢出协同机制
1. **奖励函数溢出惩罚**：排队接近阈值时给予强惩罚（权重2.0）
2. **共享经验回放**：不同路口经验混合训练，网络学习通用控制策略
3. **邻居状态增强（可选）**：22维基础状态 + 8维邻居信息 = 30维增强状态

### 5.4 高性能训练优化思路
- **瓶颈分析**：仿真41.2% + 网络更新58.8%
- **优化策略**：
  1. 网络极简化：256×256×3 → 32×32（参数量减少约30倍）
  2. train_freq提高：4 → 200（分摊网络更新开销）
  3. batch_size增大：64 → 1024（SIMD并行效率提高）
  4. 多环境并行：n_envs=2（SubprocVecEnv线性提速）
- **目标**：200+ steps/s

### 5.5 风险评估与应对
| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| 训练不收敛 | 中 | 高 | 调整学习率、探索率、奖励函数 |
| 溢出协同不足 | 高 | 中 | 添加邻居状态增强、调整溢出惩罚权重 |
| 推理延迟超标 | 低 | 高 | 优化网络结构、使用量化推理 |
| 仿真环境不稳定 | 中 | 中 | 异常处理、定期重启仿真 |

## 6. 算法实现细节

### 6.1 环境封装层

#### 6.1.1 核心环境类
- **类名**：`TrafficSignalEnv`
- **Observation Space**：660维连续空间（30路口 × 22特征）
- **Action Space**：30路口 × 4相位（离散动作）
- **关键方法**：reset()、step()、_get_state()、_apply_actions()

#### 6.1.2 单路口环境
- **类名**：`SingleIntersectionEnv`
- **用途**：单路口训练与评估，支持回合轮换路口的参数共享包装

#### 6.1.3 状态提取实现
- **函数**：`get_global_state(num_intersections=30)`
- **返回**：np.ndarray, shape=(660,), dtype=np.float32
- **车道映射**：取车道ID首字符判断方向（N/S/E/W），优先选直行车道（_0结尾）
- **容错机制**：方向缺失填0、相位越界默认相位0、路口不足填0

### 6.2 DQN网络结构

#### 6.2.1 标准配置
- **网络结构**：MLP（256 → 256 → 4）
- **优化器**：Adam，学习率1e-4
- **经验回放**：容量1,000,000，批大小64
- **目标网络更新**：10,000步
- **探索率**：1.0 → 0.05（前10%步数衰减）

#### 6.2.2 高性能配置
- **网络结构**：MLP（32 → 32 → 4），参数量约3,800（原结构的1/30）
- **优化器**：Adam，学习率5e-4
- **经验回放**：容量200,000，批大小1,024
- **train_freq**：200，gradient_steps=-1（每200步更新200次梯度）
- **目标网络更新**：4,000步
- **探索率**：1.0 → 0.02（前30%步数衰减）
- **并行环境**：n_envs=2（SubprocVecEnv）

### 6.3 训练流程

#### 6.3.1 训练主循环
1. **初始化**：启动SUMO，获取所有信号灯ID
2. **重置**：获取660维全局状态，按路口切片
3. **动作选择**：每个路口独立ε-贪婪选择动作
4. **执行动作**：批量设置30路口相位，推进仿真（delta_time=5秒）
5. **收集经验**：获取新状态，计算每路口V5.1吞吐驱动奖励，存入共享buffer
6. **网络更新**：每隔train_freq步，从buffer采样批量更新
7. **探索率衰减**：线性衰减至最终值

#### 6.3.2 多场景训练
- **三场景联合训练**：平峰(flat) / 早高峰(morning) / 晚高峰(evening)
- **高流量场景优化**：n_envs=1, buffer=100,000, batch=256, gradient_steps=10

### 6.4 基线算法实现

#### 6.4.1 Max-Pressure感应控制
- **理论依据**：Varaiya, 2013 — Max-Pressure Control of Traffic Networks
- **核心逻辑**：选择能释放最大排队压力的相位
  - NS压力 = queue[N] + queue[S]
  - EW压力 = queue[E] + queue[W]
  - 选择压力大的方向（Phase 0 或 Phase 2）
- **约束**：遵守最小绿灯时间15秒

#### 6.4.2 其他基线
- **Random**：随机选择相位（0-3）
- **Fixed-Time**：固定配时（balanced方案：30/12/30/12秒）

### 6.5 评估指标体系

#### 6.5.1 评估维度
| 维度 | 指标 | 单位 |
|------|------|------|
| Mobility（通行效率） | 排队长度、等待时间、行程时间、通行量 | 辆 / 秒 / 秒 / veh |
| Environment（环境） | 燃油消耗、CO2排放 | mL / mg |
| Safety（安全） | 停车次数、时间损失 | 次 / 秒 |

#### 6.5.2 评估方法
- **四策略对比**：Random / Fixed-Time / Max-Pressure / DQN
- **指标采集**：每步采集排队长度、等待时间、行程时间、燃油消耗、CO2排放、停车次数等
- **可视化**：柱状图、雷达图、热力图（排队长度时空分布）

## 8. 实验结果与分析

### 8.1 实验设置

## 9. 创新点与技术亮点

### 9.1 算法创新

1. **参数共享DQN协同管控**
   - 30路口共用一个网络，避免为每个路口维护独立参数
   - 通过共享经验回放实现间接协同
   - 网络结构固定，天然支持任意数量路口扩展

2. **多目标V5.1吞吐驱动奖励函数**
   - 综合排队长度、公平性（max_queue）、等待时间、安全性（overflow）、稳定性（switch）、均衡性（balance）六维目标
   - 溢出惩罚高权重（2.0）针对窄路密网特征
   - 各路口独立计算奖励，全局奖励仅用于监控

3. **高性能训练优化**
   - 瓶颈分析驱动：仿真41.2% + 网络更新58.8%
   - 极简网络（32×32，参数量3,800）+ 大batch（1024）+ 高train_freq（200）
   - 达到200+ steps/s训练速度

### 9.2 工程创新

1. **三层协同架构**
   - SUMO仿真 + Python算法 + Unity可视化
   - REST API + WebSocket双协议，兼顾可靠性与实时性
   - 30路口动作原子批量执行，保证状态时刻一致性

2. **模型轻量化全链路（模型产物已验收）**
   - 已完成ONNX导出、动态量化、结构化剪枝/蒸馏，并保持26维掩码契约
   - 正式推荐25.14 KB FP32 ONNX；INT8因真实状态精度未达门槛仅作实验保留
   - Docker容器化边缘部署尚未完成
   - 满足车路云协同低延迟要求（<5ms）

3. **路网安全优化**
   - 信号灯规范化（4可控相位）
   - 右转/掉头让行绿灯消除Unsafe green冲突
   - 最小绿灯15秒 + 黄灯过渡3秒安全约束

### 9.3 应用创新

1. **面向雄安窄路密网**：针对路口间距<200m特征优化溢出协同
2. **多时段场景适配**：早高峰/平峰/晚高峰三场景联合训练
3. **可视化展示**：Unity高质量3D渲染，实时数据仪表盘
