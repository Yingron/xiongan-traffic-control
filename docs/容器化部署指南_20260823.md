# SUMO、API 与 ONNX 边缘推理容器化部署指南

## 1. 目的和范围

本指南部署两个服务：

- `xiongan-edge`：加载正式 FP32 ONNX 模型，提供单路口和 30 路口批量推理；
- `xiongan-api`：启动 SUMO/TraCI 会话，维护 660 维状态和 30 个动作，并通过容器网络调用 `xiongan-edge`。

路网和模型均以只读卷挂载，不会被容器内部的训练或服务进程改写。

> 镜像仅包含正式推理运行时，不包含训练用 PyTorch、Stable-Baselines3、TensorBoard
> 和 Matplotlib。正式闭环使用 `/edge/predict`；开发期的 `/model/predict`（SB3 zip
> 回退接口）需要在完整训练环境中运行，不是本容器的部署依赖。

## 2. 前置条件

1. Docker Desktop 已启动，`docker info` 能返回 Server 信息；
2. 终端定位在项目根目录；
3. 以下交付物存在：
   - `sumo_files/xiongan_30.sumocfg`；
   - `sumo_files/xiongan_30.net.xml`；
   - `models/edge/peak/model.onnx`；
   - `models/edge/evening/model.onnx`。

首次构建需要从 Debian 软件源下载 SUMO 及依赖，因此需要稳定的外网连接；后续构建会复用 Docker 层缓存。

## 3. 启动

```powershell
docker compose -f edge_deploy/docker/docker-compose.yml up --build -d
docker compose -f edge_deploy/docker/docker-compose.yml ps
```

预期有两个 `healthy` 服务：

| 服务 | 主机端口 | 健康检查 | 说明 |
|---|---:|---|---|
| `xiongan-edge` | 8001 | `GET /health` | ONNX Runtime CPU 推理 |
| `xiongan-api` | 8000 | `GET /api/v1/health` | FastAPI、SUMO、TraCI |

## 4. 健康检查与 ONNX 推理验收

```powershell
Invoke-RestMethod http://localhost:8001/health
Invoke-RestMethod http://localhost:8000/api/v1/health
Invoke-RestMethod http://localhost:8000/api/v1/edge/health
docker compose -f edge_deploy/docker/docker-compose.yml exec xiongan-api sumo --version
docker compose -f edge_deploy/docker/docker-compose.yml exec xiongan-api python -c "import traci; print('TraCI OK')"
```

用峰时正式模型做一个 30 路口批量推理冒烟测试：

```powershell
$body = @{
  model_id = 'edge-real-peak-onnx-v1'
  state = @(1..30 | ForEach-Object { @(0.0) * 22 })
  action_mask = @(1..30 | ForEach-Object { @(1.0, 1.0, 1.0, 1.0) })
} | ConvertTo-Json -Depth 5
Invoke-RestMethod http://localhost:8001/predict -Method Post -ContentType 'application/json' -Body $body
```

响应应包含 `batch_size: 30` 和恰好 30 个 `actions`。这只验证模型服务；合法动作约束和信号执行由 API 会话链路再做一次校验。

## 5. API → 边缘 → SUMO 联动验收

```powershell
$session = Invoke-RestMethod http://localhost:8000/api/v1/simulation/start `
  -Method Post -ContentType 'application/json' `
  -Body '{"scenario":"real_peak","use_gui":false}'

$edge = Invoke-RestMethod http://localhost:8000/api/v1/edge/predict `
  -Method Post -ContentType 'application/json' `
  -Body (@{ session_id = $session.session_id; model_id = 'edge-real-peak-onnx-v1' } | ConvertTo-Json)

$apply = Invoke-RestMethod http://localhost:8000/api/v1/simulation/actions `
  -Method Post -ContentType 'application/json' `
  -Body (@{
    session_id = $session.session_id
    expected_transition_id = $edge.transition_id
    actions = $edge.actions
    step_seconds = 5
  } | ConvertTo-Json -Depth 4)

Invoke-RestMethod http://localhost:8000/api/v1/simulation/stop `
  -Method Post -ContentType 'application/json' `
  -Body (@{ session_id = $session.session_id } | ConvertTo-Json)
```

验收点：`/edge/predict` 需返回 `J01`–`J30` 共 30 个动作；`/simulation/actions` 返回的 `transition_id` 应递增；SUMO 日志中不得出现资产校验失败。

## 6. 场景与模型映射

| 场景 | 模型 ID | 文件 |
|---|---|---|
| `real_peak` | `edge-real-peak-onnx-v1` | `models/edge/peak/model.onnx` |
| `real_offpeak` | `edge-real-offpeak-via-evening-onnx-v1` | `models/edge/evening/model.onnx` |
| `real_evening` | `edge-real-evening-onnx-v1` | `models/edge/evening/model.onnx` |

`model_id` 必须在 `configs/edge_model_registry.json` 中标记为 `ready`。INT8 实验模型因真实状态保真度不足，不会被边缘服务接受为正式模型。

### 6.1 自动验证三个正式场景

两个服务均为`healthy`后，可从仓库根目录一次性复验三个场景：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\validate_docker_three_scenarios.ps1
```

脚本对每个场景执行`start → state → edge/predict → actions → state → rewards → stop`，
验证660维状态、30个J01-J30合法动作、30项奖励和`transition_id: 0 → 1`。脚本使用
`try/finally`释放会话，任一场景失败时返回非零退出码。默认结果文件为：

```text
logs/docker_validation_20260827/three_scenario_acceptance.json
```

成功标志：

```text
[PASS] real_peak: 30 actions, 660-D state, transition 0->1
[PASS] real_offpeak: 30 actions, 660-D state, transition 0->1
[PASS] real_evening: 30 actions, 660-D state, transition 0->1
[RESULT] PASS
```

## 7. 故障排查与停止

| 现象 | 检查方法 | 处理方式 |
|---|---|---|
| 镜像构建时无法下载 SUMO | 查看 `docker compose ... up --build` 中的 apt 错误 | 恢复网络后重试；Dockerfile 已配置 apt 下载重试 |
| edge 不健康 | `docker compose ... logs xiongan-edge` | 核对模型只读卷和模型文件路径 |
| API 不健康 | `docker compose ... logs xiongan-api` | 核对 SUMO 安装、`SUMO_HOME` 和路网文件 |
| API 无法访问 edge | `GET /api/v1/edge/health` | 核对 Compose 网络和 `EDGE_INFERENCE_URL` |
| SUMO 会话启动失败 | `docker compose ... exec xiongan-api sumo --version` | 核对 `xiongan_30.sumocfg` 及其引用资产 |

停止服务但保留镜像和日志：

```powershell
docker compose -f edge_deploy/docker/docker-compose.yml down
```

不建议执行带 `-v` 的删除命令；本配置没有创建需要清理的训练数据卷。
