> 完整启动步骤（含全部命令与验证方法）见 **[系统启动手册_20260825.md](系统启动手册_20260825.md)**，

## 演示链路（当前正式版）

```text
Unity(30路口三维) ←WebSocket 8765→ visualization_server ←TraCI→ SUMO xiongan_30
                                                ↑
                                        正式 ONNX DQN 边缘模型（edge-real-*-onnx-v1）
REST 能力演示：客户端 ←8000→ api_server（会话/660维状态/模型预测/奖励）
LLM 云脑演示：客户端 → /api/v1/llm/analyze → llama-server:8081 → 微调 Qwen2.5-0.5B
```

> 历史 PyMARL/TCP 5000 链路与 510 维状态属 20 路口时代，已废弃，勿再使用。

## 演示流程（三场景 + LLM 告警）

1. **启动服务**（顺序：llama-server 8081 → visualization_server 8765 → api_server 8000），
   命令见系统启动手册第 3 节；
2. **Unity**：打开 `frontend/CitySimulation`，场景 `Assets/Scenes/xiong_30.unity`，点击 Play；
3. **三场景切换**：Unity 右上角依次切换 平峰 → 晚高峰 → 早高峰，
   每切换一次后端自动重启 SUMO、加载对应正式模型、清空指标；
4. **LLM 云脑**：从当前状态窗口构造文本，POST `/api/v1/llm/analyze`，
   面板展示事件类别/置信度/中文建议（每 2-5 分钟一次，云脑慢周期）；
5. **基线对比**：重启 visualization_server 加 `--no-model`（固定配时基线），
   对比 DQN 模式下的排队/等待指标。

```powershell

  --expect-model-id edge-real-peak-onnx-v1 --report logs\unity_check.json
```

脚本会拒绝：非 30 信号灯、非 30 动作、非法相位、5 秒无快照。

## 正式模型 ID 速查

| 场景 | 边缘 ONNX（8765 链路） | SB3 REST（8000 链路） |
|------|----------------------|----------------------|
| real_peak | `edge-real-peak-onnx-v1` | `shared-dqn-real-peak-masked-1m-v2` |
| real_offpeak | `edge-real-offpeak-via-evening-onnx-v1` | `shared-dqn-real-offpeak-via-evening-v1` |
| real_evening | `edge-real-evening-onnx-v1` | `shared-dqn-real-evening-masked-1m-v1` |
| LLM 云脑 | `qwen-traffic`（llama-server alias，f32 GGUF） | — |

若 `/api/v1/model/predict` 返回 `MODEL_NOT_LOADED`：检查是否误用 archived 的
`shared-dqn-generalization-100k-v1`，或模型文件缺失（SHA-256 校验失败）。
